# TASY MaxBridge 0.6.1 PORTABLE

## Установка, подключение и использование

**Проект:** [LLM-3D-Scene-Bridge](https://github.com/tvolkf-star/LLM-3D-Scene-Bridge)  
**Программа:** Autodesk 3ds Max 2024  
**Сборка:** `TASY_MaxBridge_061_PORTABLE.py`  
**Статус проверки:** 11.10.2026 подтверждены локальный запуск, двусторонний обмен через Google Drive, успешный `ping` и создание тестового чайника в работающем 3ds Max 2024 по удалённой команде.

### 1. Назначение

TASY MaxBridge соединяет языковую модель с локально работающим 3ds Max. Модель формирует команду Python/pymxs, мост выполняет её внутри Max и возвращает сведения об исполнении, краткое состояние сцены и снимок активного viewport.

Мост **не моделирует самостоятельно**, не содержит специализированного ИИ и не требует агентной инфраструктуры. Передача файлов может выполняться через синхронизированную папку Google Drive либо другой файловый транспорт. Сам скрипт **не использует Google Drive API**.

### 2. Требования

- Autodesk 3ds Max 2024 с Python `pymxs` и `PySide2`.
- Файл `TASY_MaxBridge_061_PORTABLE.py`.
- Папка на локальном диске с правами записи.
- Для удалённого управления: доступный обеим сторонам файловый транспорт, например Google Drive с локальной синхронизацией.

> Внимание: `execute_python` выполняет произвольный Python-код с правами процесса 3ds Max. Используйте мост только с доверенным источником команд. Не публикуйте рабочую папку с возможностью записи посторонним.

### 3. Локальная установка

1. Создайте отдельную папку, например `E:\MaxBridge_Test` или `D:\MyMaxBridge`.
2. Скопируйте в неё `TASY_MaxBridge_061_PORTABLE.py`.
3. Запустите Autodesk 3ds Max 2024.
4. Выберите **Scripting → Run Script** и укажите файл `.py`.
5. Проверьте сообщение в Python Listener: `TASY MaxBridge 0.6.1 PORTABLE running`, затем строки `ROOT:` и `LIB:`.
6. Убедитесь, что `ROOT` указывает на **папку, содержащую скрипт**, а не на заранее заданный диск.

При запуске создаются папка `library/` и файлы `bridge_status.json`, `scene.json`. Остальные файлы появляются по мере обработки команд. Скрипт **не распаковывает архив**: архив (если используется) нужно распаковать до запуска.

**Подтверждённый тест:** скрипт был запущен из `E:\MaxBridge_Test`; рядом с ним появились `library/`, `bridge_status.json`, `scene.json`.

### 4. Рабочая папка

```text
MyMaxBridge/
├── TASY_MaxBridge_061_PORTABLE.py
├── command.json          ← создаёт управляющая сторона
├── result.json           ← ответ после обработки команды
├── scene.json            ← состояние объектов сцены
├── viewport.png          ← снимок активного viewport (если удалось сохранить)
├── bridge_status.json    ← сведения о работающем мосте
├── bridge_state.json     ← ID последней принятой команды
└── library/              ← сохранённые исполняемые .py-примеры
```

### 5. Подключение Google Drive

1. Выберите **отдельную папку** для моста. **Допускается обычная локальная папка, добавленная в Google Drive для компьютера через «Папки с компьютера».** Перемещать её в «Мой диск» не требуется. Это проверено на `E:\MaxBridge_Test`.
2. Обеспечьте её наличие **как локальной папки Windows**, доступной 3ds Max для чтения и записи.
3. Поместите `TASY_MaxBridge_061_PORTABLE.py` **в эту локальную папку** и запустите скрипт из неё. `ROOT` должен указывать именно туда.
4. На удалённой стороне используйте соответствующие файлы этой же папки Drive: обновляйте `command.json`, считывайте `result.json`, `scene.json`, `viewport.png`.
5. Убедитесь, что синхронизация действительно передаёт изменения **в обе стороны**. Наличие папки в интерфейсе Drive само по себе не подтверждает локальную синхронизацию.

#### Если ChatGPT видит папку, но не может создать `command.json`

**Не делайте вывод, что папки из раздела «Компьютер» недоступны для записи.** В реальном испытании 11.10.2026 первая попытка прямой загрузки в такую папку вернула ошибку «папка назначения не найдена». При этом чтение работало, а другие операции записи оказались успешными.

**Проверенный обходной маршрут для управляющего ChatGPT с доступом к Google Drive:**

1. Найдите тестовую папку в Google Drive и сохраните её точный **folder ID**.
2. Попробуйте повторную запись **другим способом**, а не той же неудачной операцией: например, `copy_file` существующего безвредного JSON-файла **в тестовую папку**, передав её folder ID в `parent_folder`. В испытании этот шаг успешно создал пробный файл.
3. Для первого `command.json` создайте корректный JSON-файл во временном месте «Моего диска», затем **скопируйте** его в тестовую папку с именем `command.json` (`copy_file` с `new_title="command.json"` и `parent_folder=<ID тестовой папки>`).
4. Для следующих команд предпочтительно **обновлять содержимое существующего `command.json` на месте** (`update_file` с его Drive file ID и ссылкой на подготовленные байты нового JSON). Это сохраняет ID файла и исключает накопление копий `command.json`.
5. Дождитесь синхронизации и **сверьте `result.json.command_id` с отправленным ID**. Наличие файла без соответствующего ответа ещё не означает, что команда выполнена. Проверяйте также `status`, `scene.json` и `viewport.png`.
6. Удалите временные диагностические файлы. **Не удаляйте** рабочие файлы моста и не затрагивайте другие папки.

Если повтор не помог, проверьте отдельно: доступность папки для записи конкретному подключению, путь назначения, синхронизацию Drive для компьютера и права локальной папки. **Не нужно автоматически переносить каталог в «Мой диск» или менять код моста.** Возможности разных коннекторов могут различаться.

**Для будущих ChatGPT:** первая ошибка записи через один API или через библиотечный путь `/Google Drive/...` не доказывает отсутствие доступа к папке «Компьютер». В испытании помогла комбинация `copy_file` с реальным folder ID и последующего `update_file` существующего файла. Нельзя утверждать, что команда прошла, до получения соответствующего `result.json`.

**Не переносите существующую рабочую папку другого моста и не запускайте два экземпляра, направленных на один и тот же `command.json`.** Для теста используйте отдельный каталог.

### 6. Первый тест: ping

Создайте или обновите `command.json` в рабочей папке:

```json
{
  "id": "test-ping-001",
  "action": "ping"
}
```

Мост проверяет файл приблизительно раз в секунду. После обработки откройте `result.json`: ожидается `"status": "ok"` и `"pong"` в массиве `results`. Также обновляются `scene.json`, `bridge_state.json` и `bridge_status.json`; сохранение `viewport.png` выполняется по возможности.

**Важно:** для каждой новой команды нужен **новый `id`**. Повтор уже обработанного ID игнорируется, даже если текст команды изменился.

### 7. Первый объект в Max

После успешного `ping` отправьте:

```json
{
  "id": "test-teapot-002",
  "action": "execute_python",
  "code": "o=rt.Teapot(radius=250); o.name='Bridge_Test_Teapot'; rt.select(o); rt.execute('max tool zoomextents all')"
}
```

Проверьте, что чайник появился в сцене, а `result.json` содержит `"status": "ok"`. Затем проверьте `scene.json` и `viewport.png`. Наличие чайника в сцене и успешный снимок viewport следует проверять **отдельно**: `viewport_saved: false` не обязательно означает ошибку моделирования.

### 8. Поддерживаемые действия

| Действие | Назначение |
|---|---|
| `ping` | Проверка связи |
| `execute_python` | Выполнение кода из поля `code` |
| `library_list` | Список `.py`-скриптов библиотеки |
| `library_save` | Сохранение `.py`-скрипта по имени и полю `code` |
| `library_run` | Выполнение сохранённого скрипта; можно передать `params` |
| `create_box` | Создание Box |
| `move`, `scale`, `rotate` | Изменение трансформаций объекта |
| `rename`, `delete` | Переименование и удаление объекта |

Главный универсальный способ управления: `execute_python` через нативный `pymxs`. Небольшие готовые действия являются вспомогательными, а не ограничивают набор операций.

Фактически код 0.6.1 также принимает массив `commands` внутри одного объекта с общим `id`, но для простой, предсказуемой работы рекомендуется **одна команда верхнего уровня**.

### 9. Как читать результаты

- `result.json`: `command_id`, `status`, `results`, `viewport_saved`; при ошибке `error` и `traceback`.
- `scene.json`: число объектов, имена, классы, положение, масштаб и bounding box, если доступен.
- `viewport.png`: снимок активного окна просмотра, если захват удался.
- `bridge_status.json`: состояние моста и последний статус команды.
- `bridge_state.json`: последний принятый `id`; используется для защиты от повторного исполнения.

**Не отправляйте следующую команду, пока не получили результат с соответствующим `command_id`.** Особенно важно при работе через синхронизацию, где обновление файлов может происходить с задержкой.

### 10. Типичные неполадки

**Не появились файлы после запуска.** Проверьте вывод Listener, наличие `ROOT` и права записи. Если `ROOT` указывает не туда, запустите скрипт как файл через **Run Script**, а не вставкой текста в Listener: в коде есть запасной вариант `os.getcwd()`, если `__file__` недоступен.

**Команда не выполняется.** Проверьте, что `command.json` находится именно в `ROOT`, является корректным JSON и содержит новый `id`.

**Ошибка `execute_python: empty code`.** Код должен быть в поле `code`, не `python`.

**Объект появился, но viewport не сохранился.** Проверьте `viewport_saved`. Захват изображения выполняется по возможности.

**Команда завершилась ошибкой.** Изучите `error` и `traceback` в `result.json`. Уже принятый ID не запускается повторно автоматически: исправьте код и отправьте команду с новым ID.

**Изменения не видны на удалённой стороне.** Проверьте реальную локальную синхронизацию, конфликты файлов и права доступа. Мост не управляет Google Drive самостоятельно.

**Несколько мостов мешают друг другу.** Не запускайте несколько экземпляров, читающих одну рабочую папку. Не заменяйте проверенный рабочий экземпляр без резервной копии.

### 15. Профессиональное моделирование: возможности и ограничения

MaxBridge предоставляет ChatGPT канал управления 3ds Max и обратную связь, **но не гарантирует профессиональное качество модели по одному запросу**. Точность результата зависит от постановки задачи, выбора геометрических методов, проверки конструктивной логики и последовательных итераций. Для сложных объектов нужен специалист, оценивающий результат.

**Рекомендуемый цикл:** референс и габариты → выбор принципа построения → базовая геометрия → проверка viewport → уточнение → организация сцены → сохранение.

**Общие принципы качественного моделирования:**

- Сначала определять осевые линии, габариты и конструктивные связи; затем придавать сечение и толщину.
- У сплайнов контролировать типы вершин, касательные и радиусы сопряжений. Проверять геометрию в сложных узлах.
- Параметры сечения, форму направляющей и ориентацию элемента рассматривать как разные управляемые величины.
- Соединяемые детали строить по согласованным опорным точкам, а не по независимым приблизительным координатам.
- Новый самостоятельный проект начинать в чистой сцене по согласованию с пользователем; при доработке существующей модели сохранять её состояние.
- Готовые конструкции объединять или группировать по функциональному смыслу; сохранять полезную параметрику.
- Успешное исполнение скрипта подтверждает работу моста, но **не** заменяет проверку геометрии и качества.

Документация предназначена для передачи **проверенных принципов и воспроизводимых приёмов**, а не истории внутренних учебных экспериментов. Новому сеансу ChatGPT следует сначала изучить доступные методики и текущую задачу, затем приступать к моделированию, не выдавая предположения за проверенный результат.
